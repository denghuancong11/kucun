# 审批中心询库导出愿景审查

## vision_met

审批中心的导出操作每次调用当前角色的 `/api/approvals`，只用该次响应的 `inquiries` 生成单工作表 `.xlsx`。实际浏览器下载文件包含约定的 11 列，并通过解压 ZIP 后读取工作表逐格核对了字段值、数值/文本类型、空值与数值 0、时间、状态、历史采购值和特殊文本。硒鼓、墨盒、同型号多张询库、调拨排除、计划隐藏记录、角色团队与类目范围、跨客户端新回复、未提交草稿、失败/空响应、进行中防重复点击和无业务写入均有隔离服务回归覆盖。

## gaps_found

独立审查最初发现页面验收虽设置过“处理中”，但切换“我的待办”会按现有页面规则将进度重置为“全部进度”；因此没有验证活动进度筛选时的导出。原测试也未断言类目选择与型号折叠状态在导出后保持。已补上活动进度、类目选择保持断言，并在型号折叠且采购表单有未提交草稿时导出，验证折叠和草稿保持。更新后 `npm run test:approval-export` 重新通过 10 项检查、4 次真实浏览器下载，没有遗留 follow-up issue。

## 审查证据

- 同模型独立审查读取了批准需求、当前差异、导出源码和新增浏览器回归，并独立运行 `npm run test:approval-export`；审查未发现可复现的实现缺陷。
- 补充页面状态断言后，主任务再次运行 `npm run test:approval-export`：10 项检查通过，实际下载 4 个 `.xlsx` 文件。
- 主任务已运行 `npm run lint`、`npm --prefix web run build`、`npm test`、`npm run test:source-scope` 和 `node web/scripts/approvals-page-check.mjs`，均通过。
- 浏览器测试使用隔离临时 SQLite 和随机本机端口；测试前后业务单据、库存、流水和事件快照一致。没有读取或写入现有试用数据库。
- 工作簿由测试解压并解析 OOXML ZIP 与工作表；本轮没有用 Microsoft Excel 或 LibreOffice GUI 打开文件，因此审查结论是“下载包及工作表结构/值已验证”，不声称桌面 Excel GUI 兼容已实测。

## 限制

当前用户指定的 11 列不包含单据编号。同型号多单会逐单导出，但文件中没有单据编号用于精确定位；若以后需要该能力，再单独确认是否增加编号列。
