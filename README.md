# Unismar 耗材库存系统

该仓库包含 Node.js 后端、React 前端、SQLite schema 与迁移、领星浏览器扩展及采集脚本、合成测试夹具和 Windows 部署脚本。当前数据库结构版本为 schema 38。

## 运行环境

- Windows 10/11
- Node.js 24.x 与 npm 11
- PowerShell 7（`pwsh.exe`，构建领星扩展压缩包时使用）
- Microsoft Edge；浏览器页面验收默认使用 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`

## 安装、构建和验证

在仓库根目录执行：

```powershell
npm ci
npm ci --prefix web
npm run build
```

`npm run build` 会从 `scripts/` 同步两个领星采集脚本到 `edge-extension/`，生成扩展压缩包，并构建 React 前端。`web/dist/` 和 `web/public/aster-lingxing-extension.zip` 都是可重建产物，默认不提交。

常用验证命令：

```powershell
npm test
npm run test:migration
npm run test:warehouse-fba
npm run test:teams
npm run test:teams-page
npm run test:warehouse-fba-page
npm run test:page
npm run test:ink-approval-v36
npm run test:ink-workflow
npm run test:toner-workflow
npm run test:upgrade-template
npm run test:relocation-workflow
npm run test:relocation-waybills
npm run test:transfer-workflow
node scripts/verify-system-repairs.mjs
node web/scripts/relocation-receipt-pack-page-check.mjs
```

`npm test` 和 `npm run check` 不是全系统覆盖结论；墨盒审批、升级、模板、运单、团队权限以及页面恢复等专项须按变更影响补充执行。测试证据需记录受测源码和实际构建，历史分阶段 PASS 数量不能代表当前源码全部通过。`verify-system-repairs.mjs` 验证询库回库套/箱、墨盒来源范围、数量空值和原申请量；`relocation-receipt-pack-page-check.mjs` 在真实 Edge 中验证分批录入、草稿、结果不明恢复、再次调拨及指定批次扣回。两者使用自有合成配置和新建隔离数据库，支持 `ASTER_ACCEPTANCE_OUTPUT` 指定证据父目录，每次另建 `run-*`，不覆盖旧证据。页面测试可用 `ASTER_WEB_DIST` 指向本次构建。

包含 XLSX 独立读取校验的专项需要 Python 和 `openpyxl`（仅验收使用，库存服务运行不需要）。默认调用 `python`；命令不在 PATH 时，将 `ASTER_TEST_PYTHON` 设置为已安装 Python 可执行文件的绝对路径。

页面测试需要已安装的 Edge。测试数据库、随机端口和生成文件相互隔离；默认测试输出位于被忽略的 `.test-output/` 或系统临时目录。默认测试使用合成数据。`test:upgrade-real-warehouses` 须显式提供本轮核准的静态数据库副本 `ASTER_REAL_CONFIG_BASELINE_DB` 及配置副本 `ASTER_RUNTIME_CONFIG`，仅写入再次复制的新隔离目录；不得传入正式库。原模板比对须显式指定 `ASTER_UPGRADE_TEMPLATE`，只读原文件。

## 新建本地数据库并启动

以下示例使用独立状态目录和 4174 端口，不接触其他运行中的服务：

```powershell
$env:ASTER_STATE_ROOT = Join-Path $env:LOCALAPPDATA 'UnismarInventory\development'
$env:HOST = '127.0.0.1'
$env:PORT = '4174'
$env:PROD = '1'
npm run initialize -- --state-root "$env:ASTER_STATE_ROOT"
npm start
```

首次初始化会创建 schema 38 数据库和合成演示目录；不会导入正式库存数据。停止本地开发服务可在运行窗口按 `Ctrl+C`。不要把 `ASTER_STATE_ROOT` 指向正式数据目录。

## 历史数据库迁移与私有来源

schema 1–27 的迁移需要 47 条私有在途来源，以核验并修正套/箱、库存批次和团队关联。缺少文件、格式无效或不能逐行匹配时，迁移会报错且不会提交新的 schema 版本；不得用示例文件代替，也不得跳过修正。

迁移前将本地保留的 `.local-private/legacy-inbound-sources.local.json` 放到仓库根目录下的同一路径，或在 PowerShell 中显式设置：

```powershell
$env:ASTER_PRIVATE_INBOUND_SOURCES = 'C:\private\legacy-inbound-sources.local.json'
npm run migrate
```

`scripts/fixtures/legacy-inbound-sources.example.json` 仅展示格式，其中是合成的一行样例，不满足历史迁移所需的 47 行校验。schema 28–37 使用同一受控脚本升级至 schema 38；当前版本无需重复迁移。

schema 37 的新墨盒调拨按“商务 → Alan／连续自然5h → 本团助理确认全部发出”办理。Alan 正数只调整最终数量及预锁，备注独立；0或独立拒绝释放预锁并终止，理由选填。截止前未正式提交则自动采用商务量，截止时及以后不再受理 Alan。计时由服务端持久化期限驱动，重启补办。完成后仅商务可回撤至待商务，再批准重新计时。

商务转询库同次保存本条全部商务审核量，立即释放实际净预锁；该数量从转换生效即为虚拟需求，不产生实际入出库。原调拨等待本团运营，接受后才创建唯一关联询库，初始及继承商务量均来自转换事实，直接进入采购确认；不接受不再解锁。转换询库的采购回复仍决定最终量，回撤永不重锁原批次。

墨盒询库继续允许采购／物流立即跳过未办理 Alan 并同时采购回复，Alan数量、备注、办理人和时间保持空值；Alan0仍待采购，采购最终0拒绝。采购／物流确认全量发出归档，询库始终不锁扣现有在库。页面及13列XLSX分别读取原申请、商务和采购阶段事实；完成／拒绝进入零库存变动流水，不自动发起移仓任务。

新调拨以非空 `ink_workflow_stage` 区分，空值保留schema36旧采购链。迁移将尚待商务／Alan的墨盒调拨接入新链；旧待Alan从启用时刻重新计5h，保留原商务时间与预锁。已进入采购回复／归档或已完成的旧调拨保留原链及原回撤权限。已采购回复询库继续归档，硒鼓不变，不补造历史数量。正式迁移前应停止该库存服务、备份共享状态，迁移成功后与匹配构建一同发布；旧代码不能直接打开schema37库，回退须同时恢复迁移前数据库和旧发布指针。

原运行配置中的仓库名称保存在被忽略的 `.local-private/runtime-config.local.json`。没有该本地文件时，新副本使用合成默认名称；也可通过 `ASTER_OVERSEAS_WAREHOUSES` 环境变量覆盖，多个名称以分号分隔。

移仓账号的简称、房间号保存在本地 `.local-private/warehouse-accounts.local.json`，由已确认的地址表生成，也可通过 `ASTER_WAREHOUSE_ACCOUNTS` 指定文件。部署时保留该文件和仓库配置，复制到候选版本后重新计算发布指纹；它们不提交 Git。缺少账号简称或房间号时，RMA更新会明确报错，不补值。运行合成仓库回归时设置 `ASTER_OVERSEAS_WAREHOUSES=SyntheticWarehouseA;SyntheticWarehouseB`，避免使用本机正式仓库名称。

## 硒鼓调拨与询库（schema 38）

调拨入口仍为“库存汇总 → 在库明细 → 调拨”。提交登记并预锁来源批次，商务批准按审核量调整预锁；本团助理确认全部实际发出后释放预锁并扣在库。商务拒绝只释放预锁。普通调拨继续校验真实批次、整箱倍数和可用库存。

硒鼓、墨盒同一来源批次可用件数为0且存在预锁时，运营可填写不超过该批次当前在库的整箱调拨需求。点击“提交调拨并预锁定”后先确认；选择“是”仅登记需求、不新增实际预锁，显示“待商务分配（未预锁）”，进入审批中心。选择“否”、关闭或按Esc均保留表单且不提交。确认时资格已变化则返回表单刷新库存，不自动改成普通调拨或询库。可用大于0但不足、可用0且无预锁仍按原规则拒绝。

商务先将其他待审单减批批准或拒绝、释放库存，再批准零锁需求；每单只调整自身实际预锁，同批全部调拨占用与在库升级占用合计不得超过实时在库。在库升级占满也可登记需求，但升级锁不可分配。逐单办理不保留先后优先权、不回收已批或待Alan／助理的占用。Alan仍可使用实时空余增加数量，5自然小时到期仅采用商务量、不自动发出。墨盒完成回撤仍按原申请量恢复预锁，不足则整笔拒绝。原申请量、商务量、实际占用和最终执行量分别保留。

13.1隔离验收使用新建合成库；真实页面入口要求显式提供独立构建。以下命令从仓库根目录运行，每次新建输出目录，不使用正式配置或现用4173：

```powershell
$check = Join-Path $PWD ('.test-output\req13.1-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
$env:ASTER_ACCEPTANCE_OUTPUT = Join-Path $check 'api'
npm run test:zero-available-allocation
npm --prefix web run build -- --outDir (Join-Path $check 'dist')
$env:ASTER_WEB_DIST = Join-Path $check 'dist'
$env:ASTER_ACCEPTANCE_OUTPUT = Join-Path $check 'page'
npm run test:zero-available-allocation-page
```

商务在待审核阶段可按正整数商务量整单转询库，不受原批次整箱倍数或可用量限制。转换立即释放该单账本的实际净预锁，进入“转询库，待运营确认”。本团任一运营只能接受或不接受：接受后生成唯一关联询库并直接进入“待采购确认”，原单保留为“已转询库”；不接受进入“已拒绝”，不再解锁。原批次、计划、日期和版本留在原调拨；承接询库初始量及继承商务量取转换量，原运营申请量通过来源单独立展示。转换源不再参与实际占用、发出或移仓来源统计，接受后需求只计承接询库。

询库入口仍在库存汇总。流程为“待商务审核 → 待采购确认 → 待采购归档 → 已完成”，采购审核与实际发出确认分开办理。仅采购可填写供应商最终量、CA/SC和采购备注；正整数可高于或低于商务量，0直接拒绝，回复0仍须选择CA/SC。新硒鼓询库的原申请量、商务量、采购最终量分别保留。采购确认最终量已全部实际发出，并填写发货计划号、日期、原版本后完成；不提供另一个可编辑实发量。询库全程不锁扣现有在库。物流仍可查询、导出和清空，但不能代办这两个硒鼓采购环节；墨盒及其他物流业务权限不变。

硒鼓转换仅使用 `toner_conversion_status`，不进入 `ink_workflow_stage` 或 Alan/5h 流程。询库沿用 `pending_assistant` 存储码表示归档阶段，页面显示“待采购归档”，不能凭该存储码分配给助理。完成及拒绝进入统一库存流水，询库库存变化为0；完成后只成为移仓升级候选，不自动创建任务。原13列询库导出不扩列。调拨90天移仓来源限制、周二/四21:00按创建时间隐藏终态调拨，以及询库手动清空显示的规则继续保留；按单号关联读取详情不受列表隐藏影响，也不恢复显示。

周一/三上午提交、下午商务审核、周二/四确认实际发出均为业务排班提示，不禁用其他时段。这些提示不新增钉钉、表格替代、分批或账号认证功能；完成调拨的回撤重审按13.3办理。

schema 38 迁移不重建在办单、不重放预锁，也不改历史办理人和数量。历史硒鼓询库仅依据明确的归档/拒绝事件补齐统一流水投影，保留原时刻和角色，不把旧回复0追认为拒绝。正式迁移前核对获准的在办清单，若阶段或数量变化先确认；停服后备份共享状态与旧发布指针，再迁移并发布匹配构建。回退须恢复成套的旧数据库、配置和发布指针，不能让schema37程序直接打开schema38库。

两团运营创建墨盒询库时，型号必须有本团在库或在途来源；仅在总目录或其他团有来源不能建单。有本团历史来源、当前余额为0仍可询库。此条件同时用于页面和接口，不改变硒鼓公共范围。商务转询库分别保留来源原申请量、转换商务量和采购最终量；旧转换单仅从可关联的原单事实读取原申请量，不改写历史事件。

## 审批中的调拨来源（13.2）

审批中心每条硒鼓、墨盒调拨记录的“发货方式-所属海外仓”列，分行显示运营所选真实来源批次的所属海外仓和发货方式；单据详情沿用同一含义。它不是采购回复的“发货仓库”，也不是海运、空运等在途运输方式。询库行不带此来源信息，原采购仓字段不变。

新调拨在首次成功提交时，由后端从已校验的来源批次固定两项快照；普通预锁与13.1零预锁需求一致。以后批次资料变化、审批推进、重复确认或调拨回撤，均不改变原提交快照。空项不补值，双空显示“未记录”。

旧单没有快照时，仅按原批次key精确读取当前来源，并标注“当前批次”；无法关联则显示“未记录”。不回填历史事件，不为旧单新增来源必填校验。来源不可由运营或审核人员手填修改；现有数量、预锁和角色团队范围不变。数据复用既有提交事件，schema仍为38。

## 在审批中心回撤调拨（13.3）

在审批中心找到对应调拨，“状况”紧邻右侧的操作列可办理调拨回撤。默认列表仍按原规则隐藏终态；需要找已隐藏的完成调拨时，勾选“查看已隐藏完成调拨”。该选项只增加当前角色有权读取的完成调拨，不恢复普通列表显示、不显示已清空询库，也不为回撤增加90天期限。原“移仓来源”调拨回撤入口已迁移；询库回撤及其他移仓操作留在原处。

硒鼓仅商务可回撤已完成的真实调拨，回到待商务重新审核，随后仍由本团助理发出，不接入Alan或采购步骤。回撤退回本单账本净实发量至原来源批次，并按首个原申请量恢复预锁；容量不足整笔拒绝，不部分回库或重锁。例如原申请80、实发40，退回后空余只有40，不能恢复80锁，回撤失败且库存不变。

新墨盒仍仅商务回待商务、按原申请量重锁；旧墨盒商务沿此规则，采购／物流仍按原Alan量（没有时取商务量）回待采购回复。原历史完整性、版本及下游阻断全部保留；已取消、撤回或解除的历史关联也可能阻断。原13.1零锁来源和13.2提交快照不变，不重新采集来源仓。

失败或结果待确认时，页面保留对应单据及提示。结果不明应按原请求确认，不重新发起回撤；切换角色后回原角色恢复。关闭隐藏查看或更改筛选，不会静默丢掉尚待处理的回撤单。明确失败后可关闭提示，回到正常筛选结果。

## 已确认问题修复后的办理方式

在“升级库存 → 移仓升级”找到尚未采纳包裹的流程，本团运营或管理员可更正已保存的订单号或取消流程；更正前后和取消历史均保留。已经采纳包裹的流程不提供这两个操作。同账号、订单号、FNSKU已有有效归属时，保存或更正直接拒绝，不再制造两个流程同时无法同步的状态；其他账号或FNSKU仍可使用相同订单号。

在“在库升级”中，原发起岗位、采购或管理员可取消从未完成入库且没有下游的任务，只释放该任务自身的剩余锁定。已登记过完成入库的任务不能取消。当前系统识别的是岗位，不是同岗位内的具体人员。

采购在审批中心看到具备相符原始申请、审核和零回复事件的历史硒鼓旧单时，可使用“结束历史无货询库”，无需填写虚构发货资料；结束记录发货0件、库存变动0，原历史保留。没有这些事实的零量单据不开放此入口，新单采购回复0仍直接拒绝。

普通在途导入的套/箱必须为正整数，错误会指出原文件行号，预览和确认都不能通过。部门按明确映射处理：“一团”“二团”维持原归属，“一团三部”归一团并保留原名；其他部门需先确认归属。转仓升级允许空箱规的规则不变，两次真实新增40仍累计80。

本批定向入口为 `scripts/verify-audit-core-repairs.mjs`、`scripts/verify-audit-repair-inbound.mjs`、`web/scripts/audit-repair-workflow-page-check.mjs` 和 `web/scripts/audit-repair-inbound-page-check.mjs`。页面测试须通过 `ASTER_WEB_DIST` 指定本次候选构建，均使用合成配置及独立数据库。完整交付和现存异常数据处理边界见本次《修复与验收》，不把新校验等同于历史数据已修复。

## 在途文件年份

上传含 `8.13` 等无年日期的文件后，在“文件年份”中明确填写年份，再点“按所选年份重新预览”，核对完整发货日期后确认。年份不预填，已带完整日期的行保持文件日期。文件中全是完整日期，或物流文件仅含计划号和状态时，无需额外选年。

更改年份会立即作废旧预览。切页或刷新后可恢复已明确年份的预览，但更改年份须重新上传原文件；浏览器不持久化文件本身。结果不明时年份与文件入口锁定，“重试确认”重放原请求，不能借此更改已提交日期。

## 询库来源移仓回库

采购或物流在“更新升级数量”中增加累计完成量时，按本次实际入库批次填写“本次入库套/箱”。须填写真实正整数，不预填、不默认1；每次新增入库单独填写，不同批次可不同。套/箱与本次差额入库绑定，可在入库批次和办理历史中查看。

仅修改升级中数量或减少累计完成量时，不要求套/箱。减少仍须指定未占用的原入库批次和扣回量，预锁或下游占用会阻止扣回。数量空值不等于0，明确填写0才按0办理。调拨/FBA来源继续继承原批次套/箱，转仓升级空套/箱的规则不变；既有成功请求按原键原参数确认，不补写旧批次。

## 转仓升级

首次导入读取“转仓升级”工作表第2—3行合并表头及第4行起的数据，前9项必填；退仓数量为非负整数销售套数。状况由系统设为“已在第三方海外仓”，后续字段留空。物流在升级库存中分别下载RMA、实际清点数量、升级进度更新模板，更新模板与数据流导出统一使用原模板15列，第1行空白，第2—3行纵向合并表头，第4行起为数据。Excel不含转仓单号或记录版本，按前9项固定业务资料精确匹配；无匹配、匹配不唯一或文件多行对应同一记录时整批停止。内容相同的独立记录继续保留，不能通过原模板分别更新。RMA和清点量可修正，不退回资料步骤。

升级进度填写当前升级中量和累计完成量，两者之和不得超过清点量，清点量不得超过退仓量。新增完成量按差额记入独立批次；原入库批次和本次扣回量在导入确认页面填写，只有累计量减少时生效，不加入Excel。指定入库存在当前锁定或下游占用时整批拒绝。模板预览不推进业务，确认采用事务、记录版本及同一请求去重。

转仓入库实际仓库固定为“Aster海外仓”，发货方式为“Aster海外仓-升级后库存”。这些批次为两团共享的公共库存，其他批次权限不变。套/箱留空，不自动补值，补齐前不能调拨；本轮没有新增补填入口。入库型号必须已存在于库存目录并有明确类目。schema34迁移若发现旧只读转仓记录，会列出原记录并停止，必须先确认阶段和入库事实，不能按旧完成数量自动补账。

移仓更新模板、数据流导出和运单导出共用原模板19列，第1行空白，第2行表头，第3行起为数据。移仓按型号、来源、发货计划号、发货时间、业务版本号、FNSKU、初始调拨数量、调拨店铺和订单号精确匹配；订单号空白也参与匹配。物流仍只更新RMA和原始地址。FBA剩余库存继续按来源余额扣除已移仓量计算。单号和记录版本保留在系统内部。

Excel不携带记录版本，不能据此识别文件导出后发生的所有变更；导入预览使用系统当前值，确认提交校验预览时的内部版本。非本次允许更新字段与当前值不一致时会拒绝，不能把这种值比较当作导出版本检查。运单文件仅含内部文档用途属性，不添加页面标识、单元格、隐藏列、批注或说明页；改名后仍拒绝用于导入。若另存工具删除该属性，系统无法从逐格相同的内容追溯文件来源。

原模板样式资源位于 `upgrade-workbook-template.json`，仅提取表头、样式和布局，不含原示例。独立验收 `npm run test:upgrade-template`；设置 `ASTER_UPGRADE_TEMPLATE` 为用户原文件路径时逐项比较原模板SHA-256、列宽、行高、字体、合并结构与实际导出，测试仍使用隔离业务数据。

隔离验收：`npm run test:transfer-workflow`。包含接口、实际XLSX独立读取、真实Edge页面、并发/重试、公共库存和schema33迁移；不写正式业务库。

## 领星扩展

从仓库根目录运行 `node scripts/build-edge-extension.mjs` 可同步采集脚本并生成 `web/public/aster-lingxing-extension.zip`。也可在 Edge 的扩展管理页启用开发人员模式，加载 `edge-extension/` 目录。

扩展不会保存领星密码或绕过登录验证。使用者需在浏览器中自行登录，并在扩展设置里配置库存服务地址。扩展源码位于 `edge-extension/`，采集脚本的维护源位于 `scripts/`。 移仓同步沿用“移除入库单”，读取该页面全部分页和展开后的匹配包裹商品行；按账号、订单号、FNSKU自动写入承运商、运单号与累计已发货量。同一包裹不重复扣减来源余额，同步本身不入库。此范围不保证领星未推送到该页面的历史包裹，不能表述为完整历史订单取数。
